Wipecord's first GitHub release includes the userscript and browser extensions for Chromium and Firefox. The extensions now use the standard Wipecord name and version throughout their manifests, popup and documentation; the userscript remains the primary installation.

Both extension packages include the exact generated userscript and use the same interface, confirmation, filters, rate-limit handling and Stop control. The read-only popup provides status and help links. Compatible installations coordinate through a shared page claim and a non-queued deletion lock across tabs of the same origin.

## Install or update

Install the attached userscript with your userscript manager, or [install from main](https://raw.githubusercontent.com/rafelolv/Wipecord/main/wipecord.user.js). The main link follows future updates; the release attachment is a fixed snapshot.

For Chromium, extract its ZIP, enable Developer mode in your browser's extension page, and select **Load unpacked**. For Firefox, open `about:debugging#/runtime/this-firefox` and load the Firefox ZIP as a temporary add-on. Follow the [installation and update guide](https://github.com/rafelolv/Wipecord/blob/main/docs/EXTENSION.md) for details. The minimum runtime versions are Chromium 111 and Firefox 128.

Stop active operations before updating. Keep only one Wipecord installation enabled and reload all Discord tabs afterward. The Firefox ZIP is unsigned and temporary; this release does not publish to browser stores or provide a signed XPI.

## Validation

- Clean dependency installation and `npm run check` passed: lint, 17 mocked unit tests, userscript metadata/license/syntax, matching shared-runtime hashes, minimal manifests, ZIP contents and deterministic rebuilds.
- Native extension integration passed in Chrome 154.0.8037.97, Firefox 157.0 and Brave Origin Nightly 154.1.98.28 (Chromium 154.0.8037.58). Tests used temporary profiles, loopback-only match patterns, byte-identical packaged JavaScript and simulated API responses.
- Tested idle page/popup loading, status links, both duplicate installation orders, cancelled confirmation, same-origin cross-tab exclusion without queued starts, lock release, message filters, pagination and Stop during pending search and deletion.
- The maintainer reported successful extension use before this release. Detailed browser/scenario information was not supplied; this report is separate from automated fixture checks.

The release process did not access an account or perform additional live Discord deletion. Edge, Brave stable, minimum supported browser versions, every userscript manager, live Discord DOM/CSP/API and signed/store installations have not been independently validated. Locks do not coordinate separate Discord subdomains, profiles or browsers; old scripts loaded later cannot be forced to obey the guard. See [validation details](https://github.com/rafelolv/Wipecord/blob/main/docs/EXTENSION-VALIDATION.md).

[Report a problem](https://github.com/rafelolv/Wipecord/issues) with your browser, installation type, version and reproduction steps. Omit tokens and private message data.
