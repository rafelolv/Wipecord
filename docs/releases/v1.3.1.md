Wipecord 1.3.1 waits for Discord's channel header to stabilize before mounting its interface, avoids unrelated toolbars during startup, and handles hidden or replaced headers. The maintainer confirmed that the reported Brave gray-screen problem was resolved after updating.

Since 1.2.1, Wipecord also blocks invalid patterns and date/message ranges, validates archive imports before changing targets, and provides final run summaries with an anonymous JSON export. The userscript remains the primary installation; both extensions package the same generated engine with unchanged confirmation, filtering, pacing and Stop controls.

## Install or update

Install the attached userscript with your userscript manager, or [install from main](https://raw.githubusercontent.com/rafelolv/Wipecord/main/wipecord.user.js). The main link follows future updates; this release's attachment is a fixed snapshot.

For Chromium, extract its ZIP and load the folder through **Load unpacked** with Developer mode enabled. When replacing an existing local folder, click **Reload** for Wipecord in the extension manager and confirm version **1.3.1** before reloading Discord. Refreshing Discord alone does not reload the extension's manifest or cached code.

For Firefox, load the Firefox ZIP through `about:debugging#/runtime/this-firefox` for temporary local testing. Follow the [local installation and update guide](https://github.com/rafelolv/Wipecord/blob/main/docs/EXTENSION.md) for details. The minimum runtime versions are Chromium 111 and Firefox 128. These ZIPs are unsigned local packages; this GitHub release does not publish to browser stores or include a signed Firefox XPI.

Stop active operations before updating. Keep only one Wipecord installation enabled and reload all Discord tabs afterward. The logo appears after a visible channel header stabilizes; it is not inserted on login/loading screens or message toolbars.

## Validation

- Clean dependency installation and `npm run check`: lint, 23 mocked unit tests, metadata/license/syntax, matching shared-engine hashes, minimal manifests, ZIP contents and deterministic rebuilding.
- All ten native extension scenario groups passed in Chrome 154.0.8037.97, Firefox 157.0 and Brave Origin Nightly 1.98.28 (Chromium 154.0.8037.58). Tests used temporary profiles, loopback-only matches, byte-identical packaged code and synthetic API responses. The Brave run used a visible Wayland profile with GPU enabled.
- Startup/reload, unrelated and hidden toolbars, header replacement, idle page/popup loading, duplicate installation orders, cross-tab exclusion, cancellation, stopping, filters, pagination, archive-import races and anonymous export were exercised.
- The userscript Chrome fixture passed 21 interaction checks, keyboard controls, dragging/resizing and four viewport/theme checks.
- The maintainer confirmed recovery from the reported gray-screen problem before publication. This user-reported result is separate from automated checks; the precise underlying cause was not independently established.

No real messages were deleted by the release process. Edge, Brave stable, minimum supported browser versions, every userscript manager, independent authenticated Discord checks, live rate limiting and signed/store installations remain unvalidated. Same-origin locking does not coordinate across Discord hosts, profiles or browsers. See [validation details](https://github.com/rafelolv/Wipecord/blob/main/docs/EXTENSION-VALIDATION.md).

[Report a problem](https://github.com/rafelolv/Wipecord/issues) with your browser, installation type, version and reproduction steps. Omit tokens and private message data.
