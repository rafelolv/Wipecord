Wipecord 1.3.2 addresses Mozilla's compatibility and dynamic-HTML validation warnings while preserving the existing interface, log formatting, privacy defaults and deletion safeguards. The userscript and both extension packages continue to share the exact same generated engine.

Templates are compiled into DOM data during the build; the runtime no longer parses HTML. Logs create only the four attribute-free formatting elements used by Wipecord, and other markup remains literal text. Progress and log clearing also use DOM/text APIs. Build and validation dependencies are not shipped as runtime dependencies.

## Install or update

Install the attached userscript with your userscript manager, or [install from main](https://raw.githubusercontent.com/rafelolv/Wipecord/main/wipecord.user.js). The main link follows future updates; this release's attachment is a fixed snapshot.

The Firefox extension now requires **Firefox 142 or later** to align its no-data-collection declaration with both Mozilla compatibility checks. Firefox 128–141 cannot install this extension version. Android compatibility is not declared or validated. Chromium's minimum remains 111.

For Chromium, extract its ZIP and load the folder through **Load unpacked** with Developer mode enabled. When replacing an existing local folder, click **Reload** for Wipecord in the extension manager and confirm version **1.3.2** before reloading Discord. For Firefox, load its ZIP through `about:debugging#/runtime/this-firefox` for temporary local testing. See the [installation and update guide](https://github.com/rafelolv/Wipecord/blob/main/docs/EXTENSION.md).

Stop active operations before updating, keep only one Wipecord installation enabled, and reload all Discord tabs afterward. These ZIPs are unsigned local packages. This GitHub release does not publish to browser stores or provide a signed Firefox XPI; submit the Firefox ZIP to AMO separately for review/signing.

## Validation

- Clean `npm ci` and `npm run check` passed lint, 23 mocked unit tests, metadata/license/syntax, matching shared-engine hashes and deterministic ZIP verification.
- Mozilla addons-linter 10.14.0 reported **zero errors, zero warnings and zero notices** for the generated Firefox folder and the exact Firefox ZIP. This validator is now a required check with warnings treated as errors; local validation does not replace AMO server validation or review.
- The userscript Chrome fixture passed 21 interaction checks, keyboard controls, dragging/resizing and four viewport/theme checks.
- Native Chrome 154.0.8037.97, Firefox 157.0 and Brave Origin Nightly 1.98.28 (Chromium 154.0.8037.58) passed all eleven scenario groups. Brave used a visible temporary Wayland profile with GPU enabled. Executable files were byte-identical to the packages; API responses and message data were synthetic.
- Checked hostile error markup staying inert, log clearing and empty-state restoration, default redaction and formatting, delay defaults, startup/reload, header replacement, duplicate prevention, confirmation/cancellation, cross-tab locking, filters, pagination, stopping, atomic imports and anonymous export.

No real messages were deleted by the release process. AMO server validation/review, independent authenticated Discord checks, Firefox 142, Edge, Brave stable, Android, live rate limiting and signed/store installation remain unvalidated. See [validation details](https://github.com/rafelolv/Wipecord/blob/main/docs/EXTENSION-VALIDATION.md).
